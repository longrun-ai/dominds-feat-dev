# UX 问题：仅调用一个 backfeeding=false 工具会“停住”

## 现象
当智能体在一条消息里**只调用一个** `backfeeding=false` 的工具（例如 `!!@delete_reminder`），工具执行后对话可能出现“停下来/不继续产出可见回复”的体验问题。

## 影响
- 用户容易误以为智能体卡死、无响应或工具失败。
- 智能体难以在同一轮里完成“工具操作 + 继续解释/下一步”，降低交互流畅性。
- 对依赖编排的任务流（如清理提醒后继续走查）造成阻塞。

## 复现步骤（建议）
1. 在对话中仅发送一条消息：`!!@delete_reminder 1`（且该工具为 `backfeeding=false`）。
2. 观察工具执行完成后，是否缺少后续可见文本/对话未继续推进。

## 期望表现
- 工具执行后，UI/运行时应能继续输出一段简短确认/下一步提示；或允许在同一条消息中“无 backfeeding 工具调用 + 普通文本”稳定渲染。
- 对智能体来说，应有明确的机制保证：即使工具不 backfeed，也不会导致对话流停止。

## 可能方向（待 owner 评估）
- Runtime/渲染层：当一条消息只包含 `backfeeding=false` 的 tool call 时，自动补一条系统确认消息（或让 agent 有机会继续生成）。
- Tool contract：允许/建议此类工具提供最小 backfeed（例如 `completed` + 简短结果文本），避免黑洞。
- 编排层：对“仅工具调用”做检测并提示智能体追加一句确认文本。

## 模块建议归属
- @runtime：对话推进/事件流机制（工具完成后是否触发继续生成）
- @tooling：tool contract & backfeeding 语义边界
- @webui：渲染/交互反馈（loading/完成态、是否展示确认）
