# 跨域接口契约清单（计划阶段先冻结）

目的：减少跨模块返工。凡涉及跨域协作，先在提案中冻结下面的契约最小版本，再并行实现。

## 1) HTTP API 契约（Server ↔ WebUI/CLI/QA）
- 路径：`/api/...`
- 请求：参数、body、鉴权方式（若有）
- 响应：成功体结构、错误体结构、错误分类（可重试/不可重试/需用户输入/权限不足等）
- 版本兼容：新增字段向后兼容；删除/改名必须给迁移方案
- 可观测性：请求 id、日志关联字段（如有）

## 2) WebSocket 契约（Server ↔ WebUI/CLI）
- 连接路径：如 `/ws`
- 消息类型：type 字段集合与 payload schema
- 生命周期：连接/重连/心跳（若有）
- 进度与事件：长任务的进度更新、最终结果、错误语义
- 兼容性：新增消息类型可忽略；变更既有 schema 需协商

## 3) CLI UX 契约（CLI ↔ 用户/QA）
- 命令与子命令：名称、用途
- 参数：默认值、互斥/依赖关系
- 输出：人读 vs 机读（若有 json 模式），关键字段稳定性
- 退出码：成功/失败/可重试等语义
- 日志：verbosity 等级与格式（便于排障与回归）

## 4) 工具协议与护栏（Tooling ↔ Runtime/MCP/Server）
- 工具注册：名称、输入/输出 schema
- 权限与审计：谁能调用、记录哪些信息、敏感数据处理
- 失败策略：超时/重试/降级/中止规则
- 兼容性：工具 schema 的演进策略

## 5) Runtime 事件/状态语义（Runtime ↔ 上层）
- 关键状态字段：最小集合与含义
- 事件流：事件类型、顺序保证（若有）、幂等语义
- 错误分类：可被 UI/CLI 表达的错误码/类别
- 性能/资源：可能的热点与限额提示

## 6) 回归验收口径（QA ↔ 全域）
- “必须跑”的命令集合（lint + 最小 tests scripts）
- 每个域提供：最小冒烟用例 + 失败判定 + 日志定位线索
- 变更触发回归：哪些文件/模块变动必须扩充清单
