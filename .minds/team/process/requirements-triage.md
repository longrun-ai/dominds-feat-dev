# 需求分流（PM 主导）与 PRD-lite

目的：让跨域协作在“计划阶段”收敛清楚，减少返工与接口反复。

## 1) 入口（收到新需求时）
PM 负责把需求落为 1 页 brief：
- 问题/用户价值
- 目标（1-3 条）与非目标（明确不做）
- 预期交付形态（CLI / WebUI / API / 文档 / 回归脚本）

## 2) 分流（决定 owner 与协作域）
- 主 owner：对最终交付负责（通常是 `server/webui/cli/runtime/tooling` 中之一）
- 协作域：只对自己域内的接口与实现负责
- QA：尽早介入，把验收口径与回归点写进提案

## 3) 冻结最小契约（必须在提案里写）
参考：`team/interfaces.md`
- API/WS schema、错误语义
- CLI UX（命令/参数/输出/退出码）
- Runtime 状态/事件最小集合
- 工具协议与权限/审计点

## 4) 风险、依赖与 rollout
- 依赖矩阵：本变更依赖哪些接口/模块先就绪？
- 风险：破坏性变更点、兼容策略
- Rollout：如何逐步上线（即便发布由人类执行，也需要明确顺序）

## 5) 交付与回归
- 各域 owner 给出最小冒烟用例
- PM 汇总验收标准，交 `qa` 纳入 `release-regression-checklist`
